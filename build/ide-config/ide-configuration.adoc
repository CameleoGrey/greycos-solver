= IDE code style setup

Maven is the authority for the repository's code style.
The Spotless execution in `build/build-parent/pom.xml` uses Google Java Format for Java layout,
then applies the separate import order in `build/ide-config/src/main/resources/eclipse.importorder`,
removes unused imports, and removes non-static wildcard imports.
Use explicit imports for both ordinary and static imports.
The import groups are `java`, `jakarta`, `javax`, `greycos`, `org`, and `com`, in that order.

During a normal build, the formatting execution runs in the `compile` phase.
When the `CI` environment variable is set, it checks formatting instead of applying changes.
From the repository root, explicitly apply the configured formatting with:

[source,shell]
----
./mvnw compile -Dspotless.goal=apply
----

To check formatting without applying formatting changes, use:

[source,shell]
----
./mvnw compile -Dspotless.goal=check
----

Use the Maven formatter before committing, even if your editor also formats Java.
An editor's Google Java Format integration covers Java layout; it must also respect the separate import policy.
The existing `eclipse-format.xml` file describes a different layout engine and is not the Maven Java formatter configuration.

== IDEA setup

. In _Settings -> Editor -> Code Style -> Java -> Imports_, configure the import layout
with the groups listed above, separated by blank lines.
. Set both _Class count to use import with '*'_ and _Names count to use static import with '*'_
to 999 to discourage wildcard imports, and enable _Use single class import_.
. Use the Maven commands above to format and check the project.
Do not select the Eclipse Code Formatter plugin as the repository's Java formatter.

== Eclipse setup

. Open _Preferences -> Java -> Code Style -> Organize Imports_.
. Import `build/ide-config/src/main/resources/eclipse.importorder`.
. Set the thresholds for wildcard imports and static wildcard imports to 999.
. Use the Maven commands above for Java layout.
Importing `eclipse-format.xml` into Eclipse's formatter does not reproduce Google Java Format.

== VS Code setup

Add the following import-order setting to the workspace's `.vscode/settings.json`:

[source,json]
----
{
    "java.completion.importOrder": [
        "java",
        "jakarta",
        "javax",
        "greycos",
        "org",
        "com"
    ]
}
----

Use the Maven commands above for Java layout and final import cleanup.
Remove any `java.format.settings.url` setting that points to `eclipse-format.xml`;
that setting selects the Eclipse layout configuration, not the Maven formatter.
